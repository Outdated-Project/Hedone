# 性能设计与验收

这次优化面向两类实际开销：滚动时不必要的构建与图片解码，以及播放时重复分配的媒体内存。没有修改 Flutter 引擎，也没有把动画曲线或缓存上限当作低端机帧率成绩。

## 播放路径

发现页的沉浸入口打开真实详情。同一部剧内使用竖向 `PageView.builder`，相邻页只绘制封面；滚动停稳后才请求切集。播放器和视频控制器跨集复用，尚未开始播放的详情页不创建播放器。退出后取消订阅并释放播放器；媒体插件可能延迟销毁原生上下文。

影院布局使用固定的播放器、标题和控制区槽位。旋转只改变约束和位置，不再将分页器从
`Stack` 移到 `Column` 并销毁其状态。控制区高度有界，超出部分可滚动。旋转宽度变化时
取消尚未提交的切集手势，恢复当前集；缓冲提示造成的控制区高度变化不取消正常手势。
这减少了重复挂载与状态同步工作，不代表已经测得具体帧率或 GPU 负载收益。

距离片尾不超过 12 秒，或手势进入相邻页时，尝试准备一个播放地址。地址缓存最多 3 条、存活 15 秒；同键请求共享 Future。预取不下载视频分片、不启动额外解码器，失败不影响当前播放。切集仍需加载媒体和解码首帧，弱网下不能保证瞬时无缝。

## 有界资源

| 资源 | 当前预算 | 约束 |
| --- | --- | --- |
| Flutter 图片缓存 | 32 MiB / 96 张 | 按布局尺寸与设备像素比解码；宽高分别不超过 768 / 1280 像素 |
| 播放器缓冲配置 | 8 MiB | 单播放器；不代表解码器、纹理或浏览器总内存 |
| Rust 图片缓存 | 12 MiB / 96 条 | 单项最多 2 MiB，TTL 300 秒 |
| Rust HLS 清单缓存 | 2 MiB / 32 条 | 只缓存结束清单，单项最多 256 KiB，TTL 30 秒 |
| Rust HLS 密钥缓存 | 512 KiB / 64 条 | TTL 120 秒 |
| Rust 分片缓存 | 8 MiB / 16 条 | 单项最多 2 MiB，TTL 120 秒 |
| 媒体地址映射 | 128 条 | TTL 5 分钟 |

Rust 四类缓存预算合计 22.5 MiB，计入载荷与两份索引键字节。容器元数据、分配器开销、正在接收的响应、解码帧和 GPU 纹理不在该预算内。HTTP 响应持有的共享 `Bytes` 可能在缓存淘汰后继续存活。Flutter 的图片缓存上限也不覆盖所有正在显示的图片。这些数值不能相加后当作进程内存上限。

Courierust 官方 HTTP/1 接口完整缓冲响应，单次上限 8 MiB，最多 4 个在途请求（含尚未消费的响应）；网关输出切片不等于上游流式读取。直接视频入口在上游支持 Range 和强 ETag 时按 1 MiB 连续读取，每段校验后交付，避免整视频缓冲；不支持该条件的响应及 HLS 分片缓存路径仍受上限限制。连接池每来源最多 2 个、全局最多 8 个空闲连接，15 秒后不再复用，惰性回收。地址回退、连接复用和分段读取减少了可避免的等待，但尚未测量低配置手机的首帧与帧时间。库内部复制与播放器缓存另计，32 MiB 不是进程内存上限。

收到系统内存压力通知后，应用清理图片和地址缓存，丢弃未显示的导航页面，并请求原生媒体缓存清理。当前页面继续保留。分页列表保留已加载的轻量业务记录和去重索引，尚未实现无限浏览历史的固定内存窗口。

## 数据结构与渲染

- Dart 地址缓存使用插入有序 Map，命中提升与淘汰平均 O(1)，并合并正在执行的同键请求。
- 分页使用 Set 去重；重复返回的业务 ID 不会重复生成卡片。空页停止继续分页。
- 集号使用 Map 映射到列表位置，下一集定位平均 O(1)。选集网格和竖向页面按需构建，500 集回归检查只生成视口附近的控件。
- Rust 缓存由 HashMap 与 BTreeMap 组成，查找平均 O(1)，更新访问顺序及淘汰 O(log n)。按字节淘汰替代只按条数控制。
- 分片缓存命中与 Range 响应共享 `Bytes`；测试检查范围响应的指针偏移，避免退回整段复制。
- 封面移除逐卡透明度动画，避免滚动时批量启动淡入。进度更新限制在控制区；主导航使用统一控制器，并在后台停止无关动画。

这些选择遵循 Flutter 的[性能实践](https://docs.flutter.dev/perf/best-practices)；图片预算的准确含义见 [ImageCache](https://api.flutter.dev/flutter/painting/ImageCache-class.html)。

## 实机验收

在目标低配置 Android 手机上使用 profile 构建采样，用 release 构建复核体验。记录设备型号、系统版本、刷新率、视频编码与分辨率、网络条件；debug 构建不用于帧率结论。

连续执行冷启动、快速滚动、往返切换导航、连续竖滑 30 集、拖动进度、后台恢复及 20 分钟播放。用 DevTools 记录 UI / raster 帧时间的 p50、p90、p99、超帧比例、内存曲线与 GC；同时记录首次出画、切集等待和缓冲次数。60 Hz 屏幕的单帧预算为约 16.7 ms，120 Hz 为约 8.3 ms。

重点检查内存是否持续单调增长、退出播放后是否回落，以及减少缓存后弱网缓冲是否增加。调整预算必须同时对照帧时间、内存与播放等待，不能只看一个指标。本仓库当前未取得低配置真机的这些测量结果；已经执行的检查单独记录在[验证说明](verification.md)。

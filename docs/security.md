# 安全设计

## 账号与线路

账号密码和令牌只发送到代码内固定的两个 HTTPS origin。发布页只能提供游客镜像，不能修改凭据白名单。每个账号会话绑定来源；切换线路会清除会话，身份变更与在途业务请求通过读写锁串行隔离。

原生端由系统安全存储保管凭据，Rust 不写明文会话文件。损坏或缺少来源的旧会话不会恢复。退出先删除持久化凭据，再清除进程会话并限时请求上游注销。第三方站点能否最终撤销令牌取决于该站点。

Web 访问密钥至少 32 字节。服务为浏览器分别分配随机会话、CSRF 值和 12 小时有效期；Cookie 使用 HttpOnly、SameSite=Strict，HTTPS 部署增加 Secure。业务 API 同时检查 Origin 和 CSRF，媒体入口也要求会话。上游令牌不返回浏览器，不放进 URL 或 localStorage。重启服务会使所有浏览器会话失效。

## 网络与媒体

应用启动强制严格网络策略。目标只接受不含认证信息的 HTTP(S) URL；业务线路必须是纯 HTTPS origin。网络层检查全部 DNS 答案，直连固定已校验地址并限制缓存寿命，逐跳校验重定向并拒绝 HTTPS 降级。账号请求不跟随重定向，不自动重试非幂等操作。

198.18.0.0/15 保留为明确的 FakeIP 兼容例外。使用代理或 TUN 时，最终路由仍依赖部署者的代理策略；客户端无法验证代理内部的 DNS 和转发行为。默认规则拒绝其他普通内网、回环和保留地址。

RecurseX 的 DoH 上游通过固定公网 IP 引导，Courierust 验证证书链和 IP SAN。系统 CA 不可读取或为空时使用版本化的 Mozilla 公共 CA 包。加密解析明确禁止明文递归，只允许配置中的固定 IP，并关闭上游竞速。本应用未启用 DNSSEC 验证，诊断明确标注这一点；没有关闭 TLS 校验。自动模式丢弃含受限地址的系统答案，并重新执行 DoH 查询；新答案仍整体检查并固定连接地址，不会连接任何先前被拒绝的 IP。解析缓存快照不是认证凭据，也不视作经过签名的可信文件。DNS 恢复不能解决公网 IP 本身被阻断或上游停服。

原生媒体服务仅监听 127.0.0.1 的随机端口，要求随机 256 位路径令牌、准确 Host，拒绝浏览器来源。Web 媒体使用同源服务与有效 Cookie。普通响应限制 8 MiB；媒体使用独立并发许可和按需流式读取，取消即释放，停滞 20 秒终止。视频总长度不受 8 MiB 限制，HLS 改写清单限制 2 MiB。Range 沿单一响应交付，禁止多区间请求；中途错误终止，避免重放或人工拼接不同版本。每一跳重定向仍重新检查 URL 和 DNS，TLS 校验保持开启。

HLS 子清单、音轨、密钥与初始化段全部重写到网关。相对地址以每次请求的最终重定向地址为基准。播放内容引导及可派生外部插播地址的字段不执行。封面解密后校验实际文件头，不能把任意 HTML 响应当成图片。

## 界面与诊断

帖子正文解析为 Flutter 文本和图片，不执行 HTML、脚本、iframe 或事件属性。Web 使用同源 CSP；媒体 HLS 运行时随依赖打包，不在启动时加载远程脚本。字体也随包提供。

播放日志默认关闭，字段白名单、深度、条目大小和轮转大小都有上限。媒体地址、账号令牌、密码及响应正文不进入日志；网络诊断中的代理认证信息在 Rust 返回之前脱敏。清理媒体缓存不会删除账号或观看记录。

这些控制有对应回归测试，不能替代独立审计，也不构成不存在漏洞的保证。具体实测范围见[验证说明](verification.md)。

内容 TLS 使用 Rustls 与系统 / webpki 信任锚；DNS TLS 仍由 RecurseX 内部实现承担。发布页脚本必须同源，历史镜像缓存不扩大凭据白名单。推荐画像在本机保存；用于召回的一个近期关键词会提交给当前选择的内容线路。
